# 当下玩法升级设计稿：每日镜笺

## 背景

当前“塔罗 / 梅花 / 当下”三种入口已经有不同符号来源，但用户体感仍然接近：进入模式、得到一个符号、读一段建议。这样会削弱两个关键点：

1. 用户第一次打开时，不知道为什么要在三个入口之间切换。
2. 用户第二天回来时，没有足够明确的理由再次打开。

本设计把“当下”从一次性的随机建议，改成每天一次的“每日镜笺”。它不负责回答复杂问题，而是负责给用户一个今天可以带走的微型行动锚点。

## 产品定位

三种玩法需要在用户心里形成不同任务：

- 塔罗：我有一个问题，帮我看清。
- 梅花：我站在此刻，帮我判断方向。
- 当下：今天不用分析，给我一个可以执行的小锚点。

“当下”不是更轻的塔罗，也不是没有问题的梅花。它是每日仪式，目标是让用户形成“早上或晚上来照一下”的习惯。

## 推荐方案

推荐做 **每日镜笺**，而不是打卡系统或成长等级。

### 方案 A：每日镜笺（推荐）

每天生成一次固定内容，当天再次打开显示同一条。

优点：

- 和“此镜”的安静气质一致。
- 不需要强游戏化，也能形成回访理由。
- 已有每日锚点、历史记录、账号同步基础，改造成本较低。

缺点：

- 短期刺激不如连续随机强。
- 需要把结果页做得更有收藏感。

### 方案 B：连续照见

增加连续天数，例如“已连续 3 天照见”。

优点：

- 留存信号清楚。
- 用户容易理解。

缺点：

- 容易变成普通打卡产品。
- 与当前克制品牌气质有冲突，容易让用户产生压力。

### 方案 C：每日三选一

每天给“安静 / 行动 / 放下”三个入口，用户选一个生成今日镜笺。

优点：

- 比单按钮更有参与感。
- 能让用户觉得“这条是我选出来的”。

缺点：

- 增加一步选择，可能打断“当下”的轻量感。
- 和塔罗的问题校准入口又会变近。

因此第一版采用方案 A。等每日镜笺成立后，再考虑给它加一个极轻的“今日偏向”选择。

## 用户体验

### 第一次进入当下

用户点击左侧“当下”。

页面不再出现大输入框，也不提示“无需输入问题”。它应该直接进入一个更像“今天的镜面”的状态：

- 标题：今日镜笺
- 副文案：今天只带走一件小事。
- 主按钮：照见今日

点击后生成今日镜笺。

### 当天再次进入当下

如果当天已经生成过，直接显示同一条镜笺，不再重新请求 AI。

页面需要让用户明白这不是坏了，而是产品规则：

- 标题：今日已照见
- 副文案：今天先守住这一条。
- 次级按钮：查看回看

不提供“再来一次”。如果一定要刷新，后续可以藏到设置或后台，不作为普通用户入口。

### 第二天进入当下

日期变化后，可以生成新的今日镜笺。

这就是留存核心：用户每天回来，不是为了刷随机结果，而是为了领取当天的一条行动线索。

## 今日镜笺内容结构

每日镜笺包含四个字段：

1. 色：今天留意的一种颜色。
2. 物：今天可以触碰或摆放的一件物品。
3. 时：今天适合做行动的一个时间点。
4. 行：一条今天可以执行的小行动。

示例：

```text
色：深绿
物：杯子
时：睡前十分钟
行：睡前十分钟，把明天最小的一步写在纸上。
```

文案约束：

- 行动必须具体，能在今天完成。
- 不使用占断式、承诺式或暗示结果必然发生的表达。
- 不制造恐吓。
- 不写泛泛的情绪安慰，例如“好好爱自己”。

## 结果页设计

当下结果页应和塔罗结果页明显不同。

塔罗结果页重点是牌面和问题张力；当下结果页重点是“今日可带走的物件感”。

建议结构：

```text
今日镜笺

色        物        时
深绿      杯子      睡前十分钟

睡前十分钟，把明天最小的一步写在纸上。

[已收入回看]
```

视觉上不要把它做成热闹卡片。它更像一张放在桌面上的小纸笺：

- 保留黑镜背景。
- 三个锚点横向排列，像标签而不是表格。
- 行动句最大、最清楚。
- “已收入回看”作为安静的状态提示，不做强弹窗。

## 回看里的呈现

回看面板中，当下记录需要比塔罗更轻：

```text
05.26 当下
深绿 · 杯子 · 睡前十分钟
睡前十分钟，把明天最小的一步写在纸上。
```

用户点击记录后，回到当日镜笺详情。

第一版不做收藏、不做分享图、不做连续天数。先确认用户是否愿意回来查看当天内容。

## 与塔罗、梅花的差异

### 塔罗

- 需要用户输入问题。
- 先校准问题，再抽牌。
- 结果是“问题、张力、判断、行动”。
- 适合较重的困惑。

### 梅花

- 后续应减少长输入。
- 强调此刻起卦、动静、方向。
- 结果应更像“宜进 / 宜缓 / 宜守”的判断。
- 适合下一步决策。

### 当下

- 不输入问题。
- 每天只生成一次。
- 结果是“色、物、时、行”。
- 适合日常回访。

## 数据规则

沿用已有本地和云端记录能力。

本地缓存：

- `rill_daily_anchor_v1`：保存当天镜笺。
- `rill_reflection_history_v1`：保存历史记录。

每日判断：

- 使用用户本地日期作为当天 key。
- 同一天重复进入，当下模式读取本地或云端已存在镜笺。
- 登录后同步今日镜笺，换电脑后仍能看到当天同一条。

记录字段建议：

```json
{
  "mode": "daily",
  "title": "当下 · 今日镜笺",
  "question": "",
  "anchor": {
    "color": "深绿",
    "object": "杯子",
    "moment": "睡前十分钟"
  },
  "action": "睡前十分钟，把明天最小的一步写在纸上。"
}
```

## 边界与失败状态

AI 请求失败时：

- 不保存空记录。
- 显示：这次没有照见清楚。先停一下，稍后再试。

本地存储失败时：

- 仍显示生成结果。
- 不强提示用户，只在控制台记录。

未登录时：

- 正常使用。
- 回看保存在本机。

登录后：

- 本机记录合并到账号。
- 换设备后可以拉取今日镜笺和历史。

## 第一版范围

第一版只做这些：

1. 当下入口去掉输入框，改为“照见今日”。
2. 当天已生成时，直接显示同一条。
3. 当下结果页突出“色 / 物 / 时 / 行”。
4. 回看中用更轻的格式展示当下记录。
5. 保持现有账号同步逻辑。

第一版不做这些：

- 连续天数。
- 分享海报。
- 收藏夹。
- 每日提醒。
- 多个今日选项。
- 用户自定义刷新。

## 验收标准

1. 用户进入“当下”时不会看到问题输入框。
2. 用户点击“照见今日”后生成一条包含色、物、时、行的镜笺。
3. 同一天再次进入“当下”时显示同一条镜笺。
4. 第二天可以生成新的镜笺。
5. 当下记录会进入回看。
6. 回看中的当下记录能显示三个锚点和行动句。
7. 未登录用户可以正常使用。
8. 登录后，换设备可以看到同一天的镜笺。
9. 塔罗的问题校准流程不受影响。
10. 梅花当前流程不受影响。

## 推荐实施顺序

1. 先改当下入口和结果页结构。
2. 再调整回看里的当下记录样式。
3. 最后补测试，验证每日缓存和同日复用。

这个顺序能最小化风险：先让玩法差异可见，再补留存细节。
