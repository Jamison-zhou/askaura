# 塔罗问题校准设计

## 目标

让塔罗从“输入问题后直接抽牌”改为“先整理问题，再确认抽牌”。这次不做预测增强，而是提升用户觉得“它听懂了我”的体感。

## 用户流程

1. 用户在塔罗模式输入原始问题。
2. 前端调用 `reading` Edge Function 的 `clarify` 模式。
3. 系统返回一个更适合塔罗回答的问题，以及一句简短说明。
4. 用户可以选择：
   - 照这个问题：使用整理后的问题抽牌。
   - 重新整理：基于原始问题再生成一次。
   - 我自己改：把整理后的问题放回输入框，用户修改后再整理或抽牌。
5. 确认后沿用现有抽牌流程，保存到回看里的 question 字段使用整理后的问题。

## 内容规则

校准不是算未来，也不是替用户下决定。它只把模糊问题改写成可观察、可行动的问题。

示例：

- “我和他还有可能吗？”
- 改写为：“我现在该继续投入这段关系，还是把注意力收回自己身上？”

- “我该不该辞职？”
- 改写为：“我现在真正需要判断的是离开、等待，还是先争取一个更清楚的条件？”

## 输出契约

`clarify` 模式使用 SSE，与现有 `reading` 函数一致。

必需 token：

```text
[CLARIFIED_QUESTION]
[CLARIFY_NOTE]
```

前端优先展示 `CLARIFIED_QUESTION`，`CLARIFY_NOTE` 用作小字说明。缺失时显示兜底提示，不进入抽牌。

## 非目标

- 不新增数据库表。
- 不改账号系统。
- 不改梅花和当下流程。
- 不做多轮塔罗聊天。
- 不把结果页改成长文章。
