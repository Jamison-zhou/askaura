# 此镜：日课与回看设计方案

## 背景

当前塔罗、梅花、当下三种模式的体验节奏过于相似：用户选择模式后，系统随机给出一个符号，再由 AI 输出一句行动建议。符号来源不同，但交互、反馈和结果形态接近，导致三种模式在用户心智里不够分化。

下一阶段目标是让三种模式成为三种不同的自我观察节奏，同时增加轻量留存。方向是“高级一点 + 留存一点”，不做强游戏化、不做积分、不做社交。

## 设计原则

1. 保持克制：留存来自每日仪式和回看，而不是打卡焦虑。
2. 渐进同步：未登录也能用；登录后把记录同步到云端。
3. 三种模式明确分工：塔罗偏图像投射，梅花偏当下推演，当下偏每日锚点。
4. 每次仍以具体行动收尾，延续产品核心承诺。
5. 隐私优先：用户只能看到自己的记录，前端不接触 service role key。

## 三种模式定位

### 塔罗：看见处境

适用场景：用户有一个具体困惑，想借一张图像看清自己现在的位置。

体验保持“一句问题 -> 一张牌 -> 一句行动”，但强调图像投射。结果页应突出牌面、牌名和行动建议。第一版不需要增加复杂牌阵，避免从“此镜”滑向传统塔罗工具。

记录内容：

- 时间
- 模式：塔罗
- 问题
- 牌名
- 行动建议

### 梅花：判断方向

适用场景：用户不是想看图像，而是想判断当下趋势和下一步方向。

后续应从“随机卦”升级为“此刻起卦”。第一版可以先用当前时间生成基础卦象，后续再加入用户输入的一个数字或一个字。重点是让用户感到这是一次推演，而不是换皮抽牌。

记录内容：

- 时间
- 模式：梅花
- 问题
- 卦名
- 行动建议

### 当下：今日锚点

适用场景：用户不想分析，只想拿一个今天能执行的小动作。

当下模式改为每日锚点。每天第一次打开时生成今日锚点；当天再次打开时优先显示同一个锚点，不重复随机。这样它承担留存功能，也避免用户刷结果。

今日锚点包含：

- 一个颜色
- 一个物件
- 一个时刻
- 一句行动

记录内容：

- 日期
- 模式：当下
- 今日锚点
- 行动建议

## 回看功能

新增一个轻量“回看”入口，建议放在左侧栏底部，和后台入口保持区分。入口命名可以是“回看”或“迹”。

回看以抽屉或面板呈现，不做完整新页面。第一版展示最近 21 条记录即可。

每条记录显示：

- 日期和时间
- 模式
- 牌名 / 卦名 / 今日锚点
- 用户问题（当下模式可为空）
- 行动建议

用户操作：

- 打开回看
- 查看记录
- 清空全部记录

暂不做：

- 编辑记录
- 分享图
- 连续打卡
- 成就或积分
- 收藏册

## 登录与云同步

第一版登录方式采用邮箱 + 密码。注册后立即可用，暂不强制邮箱验证。这样能降低首次使用门槛，让用户尽快完成“记录 -> 换设备回看”的核心闭环。

### 账号入口

左侧栏底部新增一个轻量入口：

- 未登录：显示“登录”
- 已登录：显示“我的”

点击后打开一个小面板或弹层，不新开页面。

未登录面板包含：

- 邮箱
- 密码
- 登录
- 注册

已登录面板包含：

- 当前邮箱
- 同步状态
- 退出登录

第一版不做：

- 昵称
- 头像
- 个人主页
- 找回密码
- 手机号登录
- 微信登录
- 社交分享

### 同步规则

用户未登录时，记录仍保存在 localStorage，主流程不受影响。

用户登录后：

1. 读取本机 localStorage 中的历史记录和今日锚点。
2. 上传本机尚未存在于云端的记录。
3. 拉取云端记录。
4. 按 `id` 去重后合并到本机。
5. 回看面板展示合并后的最近 21 条记录。

换电脑登录后：

1. 拉取云端历史记录。
2. 拉取当天今日锚点。
3. 写入本机 localStorage 副本。
4. 页面继续按本地数据渲染。

断网或同步失败时：

- 不阻塞抽牌、起卦或今日锚点。
- 记录先保存在本机。
- 下次登录或网络恢复后再尝试同步。

### Supabase Auth

使用 Supabase Auth 的邮箱 + 密码能力，不自建密码系统。

前端需要引入 Supabase JS 客户端，使用 publishable anon key 登录。登录态由 Supabase 客户端管理。

第一版暂不强制邮箱验证。未来如果加入付费、敏感数据或公开分享，再打开邮箱验证。

### 云端数据表

新增 `rill_reflection_records`：

```sql
id text primary key,
user_id uuid not null references auth.users(id) on delete cascade,
created_at timestamptz not null,
mode text not null,
question text,
symbol_name text,
symbol_label text,
action text not null,
payload jsonb not null default '{}'::jsonb
```

新增 `rill_daily_anchors`：

```sql
id text primary key,
user_id uuid not null references auth.users(id) on delete cascade,
anchor_date date not null,
color text,
object text,
moment text,
action text not null,
payload jsonb not null default '{}'::jsonb,
unique(user_id, anchor_date)
```

### 权限规则

两张表都必须开启 Row Level Security。

规则：

- 用户只能读取 `user_id = auth.uid()` 的记录。
- 用户只能插入 `user_id = auth.uid()` 的记录。
- 用户只能更新和删除自己的记录。
- 前端只使用 anon key，不使用 service role key。

## 实施顺序

推荐拆成两步，不一次性做完：

1. 先实现本地“每日锚点 + 回看记录”。此阶段不接登录，验证三模式差异和回看体验。
2. 再实现 Supabase Auth + 云同步。此阶段新增登录入口、数据库表、RLS 和同步逻辑。

这样可以先把产品体验跑顺，再接账号系统，避免同时引入太多复杂度。

## 交互流程

### 塔罗 / 梅花

1. 用户进入模式。
2. 用户输入一句问题。
3. 系统生成结果。
4. 结果生成完成后自动保存到回看。
5. 用户可以点击“回看”查看历史。

### 当下

1. 用户进入当下模式。
2. 系统检查今天是否已有锚点。
3. 如果已有，直接展示今日锚点。
4. 如果没有，生成一个新的今日锚点并保存。
5. 当天再次进入，仍展示同一条。

## 错误与边界

- localStorage 不可用时，不阻塞主流程，只是不保存记录。
- 历史记录最多保留 21 条，超过后删除最旧记录。
- AI 请求失败时不保存空记录。
- 当下模式如果 AI 请求失败，可以显示本地 fallback 行动，但第一版可先不做。

## 第一版实施范围

建议第一版只做以下内容：

1. 当下模式每日锚点缓存。
2. 所有成功结果自动保存到本地历史。
3. 左侧栏新增“回看”入口。
4. 回看面板展示最近 21 条记录。
5. 支持清空记录。

不建议第一版做连续打卡、收藏册或分享图。账号同步可以作为第二步进入，但应建立在本地回看体验已经稳定的基础上。

## 验收标准

- 塔罗、梅花、当下三种模式在使用目的上能被清楚区分。
- 当下模式同一天重复打开时展示同一锚点。
- 成功生成结果后，回看中出现对应记录。
- 最近记录最多保留 21 条。
- 清空记录后，回看面板为空。
- localStorage 失败不影响抽牌和结果生成。
- 用户可用邮箱 + 密码注册和登录。
- 登录后，本机记录可同步到云端。
- 换设备登录后，可以看到同账号历史记录。
- 用户不能读取或写入其他用户的记录。
